# Chuan 编辑版：完整文章的字图设计

默认视觉方向是有具体主体的封面与连续可读的正文，而不是组件展示页。
本版以 gzh Zen 的编辑语法为来源，重做内容装配。上游原件不改，适配在
`tools/wechat-publisher/wechat_publisher/gzh_layout.py` 的 ChuanEditorial 中，随本技能完整分发。
article.json 与 Markdown 一致使用 `gzh-chuan-editorial`。

默认提供整篇编辑排版；使用者可以选择其他主题。封面主体、构图和色彩按题材重新设计。

## 设计变量

| 项目 | 当前默认 |
| --- | --- |
| 背景 / 正文 / 强调 | 纯白 / #303a34 / #285447 |
| 辅助字 / 细线 | #79847c / #d9dfda |
| 正文 | 系统中文无衬线，16px，1.95 行高，22px 段距 |
| 章节标题 | 中文衬线回退，22px，1.55 行高，上方细线与小序号 |
| 导语 | 衬线 23px，1.75 行高，只突出开篇判断 |
| 图注 | 12px，1.85 行高，与图片紧邻，和下一段拉开 |
| 真实表格 | 13px，细横线，浅色表头，保留表头/主体语义 |
| 代码 | 13px 等宽字体，保留原始空格与换行，无伪终端窗口装饰 |
| 图片 | 整幅展示，不默认套圆角、阴影、边框或设备模型 |

这是默认排版起点。封面/插图的场景、色彩与视觉语言按本篇判断，不把一次玻璃金属样张
扩成账号所有题材的通用公式。遇到不适合衬线的题材，可按论证节奏制作专门组件，保留手机可读性。

## 语义区块与映射

| 信息任务 | 书写入口 | 排版处理 |
| --- | --- | --- |
| 栏目刊头 | byline | 小字、细线，不做彩色品牌条 |
| 开篇判断 | lead | 短而有判断的衬线导语，不重复整篇标题 |
| 正文论证 | 普通段落 | 连续阅读，按意义分段 |
| 章节转折 | h2 | 细线、小序号、衬线标题；不重复印品牌名 |
| 次级论点 | h3/h4 | 紧凑小标题 |
| 重点短语 | strong/u | 少量深墨绿或细下划线，避免一整页高亮 |
| 主视觉/证据图 | Markdown 图片 | 原比例、自然尺度，不装进 UI 卡片 |
| 图片说明 | image-note | 解释读法、来源或必要边界，不写制作过程流水账 |
| 重要引文/判断 | blockquote | 两条细线与适当留白，不添加假的名人归因 |
| 对照数据 | Markdown table | 真实表格，窄屏检查长词与列宽 |
| 可执行示例 | 代码围栏 | 淡底等宽字，逐字符保留源码 |
| 顺序/并列项 | ol/ul | 简洁列表，保留真实顺序起点 |
| 来源补注 | source-note/原文链接 | 紧邻对应依据，字体清楚 |
| 段落收束 | 普通段落/必要引文 | 不强加“总结卡”，回到本篇实际问题 |
| 联系方式 | 可选品牌卡图片 | 使用者自行配置，默认省略，不额外加框 |

## 整篇骨架

刊头 → 一句导语 → 能表达主题的主视觉 → 读者问题与论点 → 解释/证据 → 连续论证 →
局限与具体行动 → 结尾 → 可选联系卡。主视觉和解释图放在它们有信息任务的位置，
可以删减区块；不要逐项集齐组件。论文原图附近保留读图说明，不能让漂亮概念图替代实验证据。

| 内容类型 | 优先编排 |
| --- | --- |
| 技术教程 | 痛点与预期 → 原理图/真实界面 → 步骤和代码 → 验证 → 边界 |
| 软件分享 | 使用场景 → 真实功能图 → 操作路径 → 对照 → 适用对象与限制 |
| 论文深读 | 研究问题 → 机制 → 原始结果图表 → 实验边界 → 工程启示 |
| 职业规划 | 具体处境 → 判断依据 → 路径比较 → 可执行行动 → 风险与反方 |
| 新闻评论 | 变化是什么 → 一手事实 → 影响 → 未确定部分 → 读者行动 |

## 视觉验收

先打开整篇 375/390 px，再看首屏、转折、证据图、表格、代码和结尾。
检查主体在缩略图是否仍可识别，首屏有没有先堆品牌装饰，连续正文是否被反复打断，
证据图是否太小，图片和注释是否分离，强调是否过量。确认字图关系后再登记视觉审阅。
上游 HTML 检查器无错误只是平台结构检查，不能代替这些判断，更不能代表用户已认可视觉。

测试中的合成夹具仅用于验证排版与版本约束，不是已发表文章或可上传的生产样稿。

# 内容体系：从知识缺口出发

栏目由 `chuanlab.toml` 的 `publication.columns` 配置。默认 ai / papers / careers / projects 是一个适用于计算机领域的起点，
不是使用者必须经营的账号方向。栏目回答“属于哪个知识领域”，内容形态回答“解决什么阅读任务”。
`kind` 是工具使用的类型字段，与栏目分开；形态包括 guide / explainer / analysis / paper-reading / project-case / update。

## 编辑定位

选题同时观察读者反复遇到的问题、尚缺的基础章节、已有内容的后续、真实项目材料以及值得解释的新研究。
热点仅是入口之一；AIHOT 注意力分只用于事件线索，不作常青教程与项目案例的统一门槛。
每个候选说明读者场景、读后能力、材料支持的最强结论、关键缺口、本篇增加的解释与既有内容关系。
没有增量时，缩小承诺、补更旧章或暂缓，不为发布频率扩写公告。

没有实验条件时，可使用有依据的机制推演、透明计算或标明合成输入的可运行教学案例。
不强制每篇实验，也不把“没实测”作为只转述摘要的理由。深度按 [深度标准](depth-standard.md) 审核，不用字数、引用数或自评高分证明。

## 默认方向

| 栏目 | 阅读承诺 | 研究边界 |
| --- | --- | --- |
| AI | 理解机制、完成任务、判断失效与成本 | 模型更新应改变一个具体判断；工具列表不代替教学 |
| papers | 重建问题、方法选择与证据链 | 覆盖计算机各分支及跨学科，明确预印本/接收/发表状态 |
| careers | 为具体人群和岗位建立方向、能力与作品证据 | 记录地区、时间和统计口径，不从局部招聘样本推出全国结论 |
| projects | 用用户真实材料解释项目的使用、设计、验证与迭代 | 只使用本次明确提供的项目，不预置项目名、经营成果或产品计划 |

AI 可按任务协作、基本原理、工程实践与具体工作台组织路径，类比之后回到真实机制与架构假设。
论文可做一篇深读、相邻工作的假设比较、推导或复现笔记；作者结果与本次执行结果分开。
就业覆盖计算机行业不同技术岗位；每篇限定人群与决策阶段，能力通过什么作品或交付被观察到。
项目按阶段选择说明、场景教程、设计拆解、复盘或短公告。没有功能与阶段材料时先补材料，不能从名字推测。
商业项目应解释利益关系，不包装成无关联的独立测评；工具执行记录不能自动证明用户亲历或经营成果。

## 系列与学习路径

按实际需要填写 `series_id`、`project_id` 与“前置 / 本篇 / 下一步”，独立文章可以不属于系列。
同一知识点优先在稳定章节维护；公开导航只指向已可访问的内容，不为连载扣住本篇答案。
栏目均衡通过滚动审视发现空缺，不规定固定频率、篇数或比例。临时偏好不自动升级为所有使用者的规则。
